## 2026-11-06 双向 PWM 解锁瞬态修复

现场反馈：摇杆回中、解锁后履带短暂转动随后停止，上锁立即停止。
用户回传输出曾为 MAIN1=1100、MAIN2=1337 us，后续采样为两路1500 us；
尚无同一次解锁的完整同步波形，不能据此排除其他瞬态来源。

原输出限幅器在解锁前500 ms内，将上锁值线性渐变到当前目标。
本车上锁值0、双向停止中位1500 us，这条路径会经过反向控制脉宽。
现在只对按实际输出通道标记的双向电机跳过这段解锁渐变，
直接使用目标值（零控制时为MIN/MAX中点）；普通通道保持原渐变。
未解锁、无效输入、kill/lockdown及失效处理的既有路径不改。
本改动没有增加中位参数，不改变方向、端点或控制器自身加减速。

`Tools/vgsolar/check_arming_neutral.py` 在宿主机编译实际输出限幅状态机，
用可控时钟和PWM映射替身检查解锁/再次解锁、中位、正负指令、无效输入、
上锁和普通通道渐变。原实现先复现中位检查失败，修复后应通过。
测试不替代真实PWM引脚波形；刷写后先断履带动力采集解锁前后输出，
再架空短测停止行为，不能直接进入地面行驶。

## 2026-11-06 舵机预解锁到解锁的输出连续性

CH8 经 RC AUX 直通 MAIN3、允许预解锁控制时，舵机在预解锁阶段已经收到
有效 PWM；正式解锁后原限幅器仍会进入 500 ms 电调渐变，从 DIS=0 重新
增加脉宽，产生短暂无效/低端输出。宿主回归已复现这条输出不连续路径。

现在对允许预解锁控制的输出提供器直接采用目标脉宽，覆盖舵机、RC 直通
和通用外设；普通单向电机仍保留解锁渐变，双向电机保留既有中位处理。
无效输入、上锁、kill/lockdown 和 termination 路径不改。
`check_arming_neutral.py` 增加高/中/低目标脉宽的预解锁到解锁连续性回归，
修复前失败，修复后通过。实板具体功能映射、预解锁参数和波形仍需回读。

用户另报未连接 QGC 时 Manual 模式无法驱动，当前根因未确认。需要区分
遥控来源选择、模式槽位、实际解锁、地面站失联动作及断 USB 后供电状态；
不能以连接 QGC 后能动作就认定手动控制必须依赖地面站。

## 2026-11-06 无 USB 时航电电压误判

用户截图显示 Manual/Not Ready，解锁拒绝原因为 `Avionics Power low: 0.00 Volt`。
只读回查中 `system_power.voltage5v_v=0`；当前板级配置和原 AP VGSolar hwdef
都没有定义独立 5V 航电 ADC 通道。board_adc 将未采样字段保留为零，原
PowerChecks 在无 USB 时按真实低压处理；插 USB 时跳过轨电压检查，因而
能解释插 USB 可解锁、拔 USB 拒绝的差异。仍需更新后独立供电实测确认。

板级现在显式声明 `BOARD_HAS_NO_5V_SENSE`，PowerChecks 只对该能力标记
省略未监测的 5V 电压上下限判断；不伪造 5V 读数，不设置 CBRK_SUPPLY_CHK。
缺少电源输入、缺少 system_power、冗余电源及过流检查保留；动力电池检查
不改，其他板型原有零伏和高压拒绝仍保留。本板缺少独立电源有效/过流
检测的硬件定义，保留软件检查不等于已经具备相关测量能力。

`Tools/vgsolar/check_power_sense.py` 编译生产检查函数，分别验证有/无监测
两种配置的零伏、高压、USB行为、消息/输入缺失、冗余和过流路径。
该修改解决板级能力适配，不代表真实供电稳定性已验收。
